# U1 Looks (Classic and Paper) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A student can choose between the Classic look (today's app, unchanged) and a warm Paper look in Settings; the choice is saved to their profile and applies across the signed-in app.

**Architecture:** One new profile column (`look`). The signed-in shell puts `data-look` on `.app-root`; `globals.css` holds one block of colour variables for Paper (light and dark) that override the existing variable names, so no component needs restyling. The same palette lives in `lib/appearance.ts` (`LOOKS`) so tests can check contrast and that the CSS and TypeScript values agree.

**Tech Stack:** Next.js 16 (read `node_modules/next/dist/docs/` if you touch routing or layout files), React 19, Tailwind 4 (`@theme inline`), Supabase, Vitest (unit and DB), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-08-u1-themes-design.md`

## Global Constraints

- Classic must look exactly as today: its `:root` and `.dark` values are not changed; existing students default to `classic`.
- Paper changes colours and the three Home tile tints only: no layout, spacing, radius or feature change.
- The student's font choice always wins; Paper's serif greeting applies only when `look === 'paper'` and `font === 'sans'`.
- Accent colour and light/dark/system keep working on top of either look.
- Text must stay WCAG AA (4.5:1): `--fg` on bg/raised/surface; `--muted` on bg/raised and on each Home tile tint; every accent's `text` (light) and `textDark` (dark) on the look's bg and raised.
- Pages outside the signed-in app (auth, onboarding) and print are not themed.
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; git identity is kadubofour's noreply, never the Gmail.
- Never handle API keys or secrets. Do not push or merge to `main` without asking (main deploys).
- Windows project: write files containing backslashes with the Write/Edit tools; `.tsx` files may be CRLF, keep line endings when editing.
- Each task ends with its tests green, `npx eslint` and `npx tsc --noEmit` clean, and a commit.

## Rulings (differences from the spec, and why)

- **Home tile tints are lighter than the spec's first values.** The spec said `#F6D9C4 #F3E6A8 #CFE6D6` (light) and `#4A3223 #4A4220 #243A2E` (dark); `--muted` on those was 3.6–4.6:1. Use `#F8E4D4 #F7EDC4 #DDEEE3` (light) and `#3A2A1F #38331B #1F3027` (dark): `--muted` on them is 4.55–5.00:1. Task 4 updates the spec's table.
- **The CSS and `LOOKS` are kept in step by a test**, not generated: `tests/unit/lookCss.test.ts` reads `app/globals.css` and compares every colour with `LOOKS`.

## Review Focus

- A student with an older cached profile (no `look`) or an unknown look name must get Classic, not a broken page (Task 1 `lookOf`, Task 2).
- Dark mode inside Paper must use the Paper dark values, not Classic dark (Task 2 CSS test and E2E).
- Classic dark must not accidentally lose its tile colour (the `--tile-*` variables are defined in both `:root` and `.dark`; Task 2).
- A failed save of the look must roll back to the previous look (Task 3).
- The picker must be keyboard-usable like Accent and Font (Task 3).

```ts
import { describe, it, expect } from 'vitest'
import fs from 'node:fs'
import { LOOKS } from '@/lib/appearance'

const css = fs.readFileSync('app/globals.css', 'utf8').replace(/\r\n/g, '\n')
// The declarations inside the first rule whose selector is exactly `selector`
function block(selector: string): string {
  const start = css.indexOf(`${selector} {`)
  expect(start, `no rule for ${selector}`).toBeGreaterThanOrEqual(0)
  return css.slice(start, css.indexOf('}', start))
}
const value = (b: string, name: string) => new RegExp(`${name}:\\s*([^;]+);`, 'i').exec(b)?.[1].trim().toLowerCase()
const KEYS = ['bg', 'raised', 'surface', 'line', 'fg', 'muted'] as const

describe('globals.css matches LOOKS', () => {
  it.each([
    ['classic', 'light', ':root'], ['classic', 'dark', '.dark'],
    ['paper', 'light', '.app-root[data-look="paper"]'], ['paper', 'dark', '.dark .app-root[data-look="paper"]'],
  ] as const)('%s %s colours', (look, mode, selector) => {
    const b = block(selector)
    for (const k of KEYS) expect(value(b, `--${k}`), `${look} ${mode} --${k}`).toBe(LOOKS[look][mode][k].toLowerCase())
  })
  it('Paper tile tints match, in light and dark', () => {
    for (const [mode, selector] of [['light', '.app-root[data-look="paper"]'], ['dark', '.dark .app-root[data-look="paper"]']] as const) {
      const b = block(selector)
      ;(['a', 'b', 'c'] as const).forEach((t, i) => expect(value(b, `--tile-${t}`), `${mode} tile ${t}`).toBe(LOOKS.paper[mode].tiles[i].toLowerCase()))
    }
  })
  it('Classic tiles are the plain card colour in both modes, so Classic is unchanged', () => {
    for (const selector of [':root', '.dark']) {
      const b = block(selector)
      for (const t of ['a', 'b', 'c']) expect(value(b, `--tile-${t}`), `${selector} --tile-${t}`).toBe('var(--raised)')
    }
  })
  it('defines the tile classes and a matching page background behind Paper', () => {
    for (const t of ['a', 'b', 'c']) expect(css).toContain(`.tile-${t} { background: var(--tile-${t}); }`)
    expect(css).toContain('body:has(.app-root[data-look="paper"])')
  })
})
```
